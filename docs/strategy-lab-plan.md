### Real problems found

1. **Multi-stock run is broken in production.** The UI posts to
   `POST /live/strategy-lab/validate`, which serves results from precomputed bar
   packs. `lab_meta`, `lab_bars`, `lab_ibars` and `lab_results` are all empty in
   production and the two jobs have no scheduler entry (`job-manifest.ts`:
   "registered only"), so every run returns "price data is still being prepared".
2. **Settings drift.** The server run takes only `stop/tp/trail/costBps/years`
   (`normalizeCfg`), so ATR stops, R targets, trail activation, breakeven and
   max-hold shown in the exit plan never reached it; the single-stock report
   used the full exit plan. Defaults also differed (8% stop forced).
3. The server returns only stocks whose entry rules are met now; there is no
   table of all tested stocks.
4. Engine issues listed in the task (annualisation by bar count, √252 for weekly,
   intraday exposure from the collapsed curve, `bars ≥ N` holding N+1 bars,
   SMA-ATR, O(n·N) `priorMax/min`, open trades without exit cost, 5-year-only
   coverage, parser mismatches, `Nm` read as minutes).

## Architecture decision

The multi-stock run moves to the **browser** (Web Worker), as in the prototype:

* Universe: the **50 largest S&P 500 constituents by market cap**, from a new
  `GET /live/strategy-lab/universe` (FMP constituents + FMP quotes, cached 24 h)
  — no hardcoded ticker list (`LAB_UNIV` is deleted).
* Bars: `GET /live/strategy-lab/bars` (server-side FMP, split-adjusted EOD;
  intraday paged and filtered to 09:30–15:59 ET), now accepting a calendar-day
  span for daily so the warm-up can be fetched before the window.
* The same downloaded bars and the same `valCfg()` object feed the table row and
  the drill-in report, so the report's CAGR equals its row by construction.

The server-side precompute pipeline (`validate`, `lab-results`, jobs) is left in
place but no longer called by the UI; its engine copy is kept in sync.

## File-by-file

### `app/iq/sl/engine.js` (+ byte-copy to backend `engine.ts`)
* `metrics(eq, trades, tf)`: years = calendar span / 365.25; `cagr: null` under
  1 year; Sharpe/Sortino ×√52 weekly, ×√252 otherwise.
* `runRules`: `cfg.tf`; exposure from the un-collapsed intraday curve; `bars`
  counts the entry bar so `bars ≥ N` and `maxBars N` both hold N bars; still-open
  trade marked net of exit cost; warm-up check (`warmup(spec)` + ≥ 20 test bars)
  instead of `bars.length < 260`; returns `null` only for too little history.
* `checkRules(spec, tf)`: "needs intraday candles" for session indicators on
  `d`/`1w`.
* ATR with Wilder smoothing; `series(bars, operand)` exported.
* O(n) `priorMax`/`priorMin` (monotonic deque); MACD EMA(26) computed once.
* `buildEvidence(res, ctx)`: coverage vs the requested period (≥ 98 % span,
  max gap 5 d daily / 10 d weekly / no missing session intraday); limitations
  name the real timeframe.
* `parseRules` / `parseTimeframe`: the cases listed in the task.
* `warmup(spec)`, `insufficient` reporting.

### `app/iq/sl/lab-controller.jsx`
* `valCfg()` = `{ ...exitPlan(labCfg).eng, costBps, tf, years | idays }`; used by
  the run, the report, the chart levels, the stale signature and Save/Edit.
* Exit-plan defaults: stop None, no 8 % fallback; AI `stop/tp/trail` mapped onto
  the exit-plan keys exactly; library strategies may carry `risk`.
* Multi-stock run in a Web Worker (`lab-worker.js`), progress via functional
  `setState`, results cache keyed on symbol + spec + cfg + last bar date + last
  close; insufficient-history counted separately from fetch failures.
* Results view-model: summary over all tested stocks, sortable table (Signal,
  Price, CAGR, B&H CAGR, Excess, Sharpe, Max DD, Win %, Trades), meta line.
* Row click → step 3 report for that stock with the same bars and cfg.
* Delete: `LAB_UNIV`, `runScan`/`fetchScan`/`fetchIntra`/scan view-model, step 2
  (`labS2`, `cfgDir/cfgTf/cfgUniv/cfgSize/cfgSym/cfgStop/cfgTp/cfgTrail`), step 4
  (`labS4`, `matches`, `labMatches`, `labAlert`), Ask mode (`aiFacts`, `aiFit`,
  `aiModes`), the return-window selector, `labStrats`, sample leftovers, group
  test (superseded by the results table).
* Compare-all / variance behind explicit buttons, memoised; compare-all lists
  only strategies valid for the timeframe.
* Library: tab "Library"; `mom`/`pead` disabled with their "Needs …" reason;
  description fixes (`hi52`, `pead`, `power`, `f_vwap`, gap strategies).
* Rule editor: lookback select shows non-preset N; OR-group rows get lookback,
  period and tooltips; A-side Number value input; periods capped at bars
  available.
* Save/Edit/Delete through `/live/strategy-lab/saved` (per user); localStorage
  only as an offline cache; one-time migration of `mc_lab_saved_v1`.
